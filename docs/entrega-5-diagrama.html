PoC DevSecOps: Shift Left e Shield Right em Kubernetes

Documento visual para exportar em PDF e usar na entrega da Entrega 5. O foco e mostrar a complementaridade entre pipeline, WAF e runtime security usando o OWASP Juice Shop como alvo.

1. Arquitetura geral da PoC

A PoC foi organizada em tres camadas de defesa. O Shift Left atua antes do deploy, no pipeline CI/CD. O Shield Right atua em duas frentes: na borda HTTP com WAF e em runtime com Falco.

Leitura do diagrama: a mesma aplicacao e protegida em momentos diferentes do ciclo de vida. O pipeline tenta impedir o avancar do artefato, o WAF bloqueia trafego malicioso e o Falco detecta comportamento suspeito durante a execucao.

2. Comparacao entre Shift Left e Shield Right

Shift Left

Antes do deploy

  • Build da imagem
  • SAST com SonarQube Cloud
  • SCA e image scan com Trivy
  • Quebra da pipeline quando o gate falha
Shield Right

Na borda HTTP

  • NGINX Ingress
  • ModSecurity habilitado
  • OWASP CRS ativo
  • Bloqueio de SQLi e XSS com 403
Shield Right

Em runtime

  • Falco observando syscalls
  • Falcosidekick encaminhando alertas
  • Deteccao de exec no container
  • Deteccao de leitura de arquivo sensivel

Cenario 1 - Shift Left atuando

Pipeline

Objetivo: demonstrar que um artefato inseguro e bloqueado antes de qualquer push ou deploy. No laboratorio atual, a evidência principal e o job sca falhando no Trivy por achados do Juice Shop.

Abrir no navegador: GitHub -> repositorio -> Actions -> workflow "DevSecOps Pipeline" O que capturar: - build aprovado - sast aprovado - sca falhando - trecho do log do Trivy com o achado e exit code 1

Cenario 2 - Shield Right atuando na borda

WAF

Objetivo: demonstrar que o WAF intercepta requisições HTTP maliciosas antes de atingir o Juice Shop.

Comando rapido: cd "/l/disk0/kauaidb/TCC POC" ./scripts/test-waf.sh "http://192.168.49.2:31191" "juice-shop.local" Ou, se quiser individualmente: curl -i -H "Host: juice-shop.local" "http://192.168.49.2:31191/rest/products/search?q=test%27%20OR%201%3D1--" curl -i -H "Host: juice-shop.local" "http://192.168.49.2:31191/search?q=%3Cscript%3Ealert(1)%3C%2Fscript%3E" Log de apoio: kubectl logs deployment/ingress-nginx-controller -n devsecops-lab --tail=200 | grep -E "ModSecurity|403|juice-shop.local|/search|/rest/products/search"

Terminal com SQLi e XSS retornando 403

Logs do ingress-nginx com ModSecurity

Cenario 3 - Shield Right atuando em runtime

Falco

Objetivo: demonstrar que o Falco detecta comportamento anomalo dentro do pod do Juice Shop mesmo depois do deploy.

Comando principal: cd "/l/disk0/kauaidb/TCC POC" ./scripts/test-falco.sh devsecops-lab "" /nodejs/bin/node 5 1m Log manual complementar: kubectl logs daemonset/falco -n devsecops-lab --since=2m | grep -E "Exec detectado|Leitura de arquivo sensivel|juice-shop|/etc/passwd" Validacao visual: kubectl port-forward -n devsecops-lab svc/falco-falcosidekick-ui 2802:2802 Abrir no navegador: http://127.0.0.1:2802 login: admin senha: admin
